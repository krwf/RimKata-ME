# 문 캐시

문 생성·건설 완료·재설치·세이브 로드 시 실제 생성된 문을 기준으로 준비하는 재생성 가능한 캐시입니다. 안개 속 문도 포함합니다. 돌파 시 선택한 닫힌 문의 정보를 다시 준비하고, 확정한 그림은 돌파 상태와 문 잔해의 세이브에 보존합니다.

저장 경로는 `door/<게임 ID>/<모드 환경 SHA256>/`입니다. 게임 ID는 세이브의 GameComponent에 저장되며 같은 플레이의 자동 저장·다른 이름 저장에서는 유지됩니다. 기존 세이브에 처음 추가된 ID는 한 번 저장한 뒤부터 재로드해도 유지됩니다.

- `environment.xml`: 현재 게임 버전, 활성 모드의 실제 순서·패키지 ID·표시 버전, 로드된 어셈블리 이름·MVID. 이 내용으로 모드 환경 폴더를 구분합니다.
- `<SHA256>.xml`: 문 종류·출처·재질·스타일·색상·그래픽 정보.
- `<SHA256>.render.xml`: 닫힌 문 주요 패널의 메시·크기·재질 구성. `door-panels-v2`는 방향별 실제 텍스처·마스크와 여러 칸 문의 좌우 패널·상부 패널을 기록합니다. 저장할 수 없는 그래픽 정보는 사유를 기록하거나 준비 실패로 알립니다.
- `Building_Door`의 하위 클래스, `Graphic_Multi`, 렌더 메서드에 다른 모드의 패치가 있다는 이유만으로 제외하지 않습니다. 문 패널의 기본 출력 구조를 사용하며 모드의 임의 C# 렌더 전체를 실행·복제하지 않습니다.
- 기존 `vanilla-door-movers-v1` 형식으로 세이브에 남은 문 잔해도 계속 복원합니다. 새 형식은 내용 해시가 달라져 기존 캐시를 삭제하지 않고 다시 준비할 수 있습니다.
- 두 문서 내용의 해시를 공유하므로 같은 모습은 중복 저장하지 않습니다. 문 위치와 실제 방향은 공용 캐시에 넣지 않고 기술 발동 시 따로 확정합니다.
- 환경 정보는 게임별 첫 캐시 준비에서 한 번 계산합니다. 모드 파일 전체의 내용 체크섬은 아니므로 표시 버전이 그대로인 XML/텍스처만의 변경을 모두 식별하지는 않습니다. 문 자체의 현재 정보·렌더 구성 해시 검증은 별도로 유지합니다.
- 대기 중인 문과 준비된 메모리 캐시는 GameComponent별로 분리합니다. 다른 게임으로 넘어간 뒤 실행된 이전 게임의 콜백은 문 상태를 읽기 전에 중단합니다.
- 이 파일들은 게임 Def가 아니며, `Defs` 로더나 세이브의 문 정보를 대체하지 않습니다. 임의 모드의 C# 렌더 코드, 부속 효과, 그림자를 복제하지 않습니다.
- 생성/로드의 긴 작업이 끝난 뒤 준비합니다. 매 틱·매 렌더 파일 읽기나 전체 폰/맵 검색은 없습니다. 기술을 사용할 때 선택한 문 하나의 정보를 다시 준비합니다.
- 파일이 없거나 손상·구버전이면 해당 문을 다시 준비할 때 재생성합니다. 현재 게임에서 이미 준비한 조합은 메모리 캐시를 사용하므로 파일을 지웠다면 세이브를 다시 불러와 새로운 게임 인스턴스가 생성될 때 복원됩니다.
- 이전 구조인 `door` 루트의 임시 XML은 읽거나 이전하지 않습니다. 새 경로에서 현재 게임의 문을 기준으로 다시 생성하며 기존 임시 파일은 그대로 둡니다.
- 자동 생성 파일은 Git에서 제외합니다. 문을 그리거나 파괴하는 실행 코드는 이 폴더에 저장하지 않습니다.
